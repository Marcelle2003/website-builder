# Website brief

The AI creates and maintains these notes from conversation and project evidence; the owner does not need to fill out this document. Keep it short and current, preserve owner edits, and replace these prompts with actual information. Separate confirmed decisions, agent assumptions, and open questions. Do not store secrets or duplicate the conversation.

## Purpose and visitors

Business/site purpose, intended visitors, and their primary action.

## Scope and behaviour

Requested pages and features, roles if applicable, existing behaviour to preserve, and work deliberately deferred.

## Creative direction

Brand name, tone, references, colour roles, typography, image treatment, and decisions the owner likes. Record accepted motion direction, significant interactions, and mobile/reduced-motion adaptations without treating every reference effect as a requirement.

## Content and editing

Supplied versus demonstration content, imagery sources/credits, WordPress-editable pages/blocks/fields, and publishing/cache behaviour. State what editors can change and which layout or animation changes are made through the AI. Preserve the actual editing model when adopting an existing site.

## Forms, attribution and favicon

Cognito organization/form references and connection status (no credentials), actual field mappings and ADMIN/ADMIN visibility rule, script locations, first-touch/90-day attribution, existing consent integration if present, and real prefill/submission checks. Record an explicit alternative provider or unsupported embed constraints. Favicon: approved asset and verification, pending choice/asset, or explicit owner skip.

## Project and preview

Stack and selected versions, local WordPress environment and hosting target, where run instructions live, local preview/admin URLs, and relevant configuration names without secret values. Record an existing non-WordPress stack accurately; this brief does not authorize migration.

Keep detailed architecture and verified commands in `AGENTS.md` and the run guide; reference them here instead of maintaining competing copies.

Potential improvements to the reusable Website Builder workflow belong in local `SKILL_FEEDBACK.md`, following the skill's feedback guidance. Keep this brief focused on the website; do not put private inbox paths here.

## Latest work and verification

Completed changes, actual checks/evidence, known limitations, and the next requested step.
